# Working agreement

We're getting close to go-live. From now on:

- **Keep every change small — roughly 10-20 lines per change.** No big refactors, no drive-by cleanups, no touching unrelated code "while you're in there."
- **Break every task down to a granular level before writing any code.** Discuss the breakdown with the user first — list the individual small changes a task will take, in order — and get agreement before implementing.
- If a task genuinely can't fit in ~10-20 lines, say so explicitly and propose how to split it into multiple small changes/commits rather than doing it as one large one.

This applies to backend, frontend-web, and marketplace-web alike.
